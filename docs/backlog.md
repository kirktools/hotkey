# 后续工作

以下事项已确认需要跟进，尚未实现或验证。

## 截图插件接入前

1. 修复宿主与 SDK 双向管道的主线程同步写入：非阻塞传输、队列上限、独立超时和有界停用；增加停止读取等故障测试。
2. 在执行新插件与握手之前校验签名有效性及更新身份连续性。身份改变需明确确认；ad-hoc 签名不能证明发布者连续性。
3. 使用最小截图插件实测 responsible code 与录屏权限归属，以及宿主／插件分别更新后的授权表现。涉及实际授权前取得明确允许，不自动重置隐私权限。
4. 根据权限验证结果确定进程启动方式，再增加最小会话协议：接受／完成、会话 ID、结束事件、取消请求，以及重复触发的明确行为。

保留独立进程和 JSON 协议。截图插件管理选区、编辑、导出及会话内按键；宿主管理快捷键入口和插件生命周期。现有截图项目本身不在这些待办的修改范围内。

## 内置插件边界

应用操作已位于独立 `AppSwitchPlugin` 模块，命令分发只依赖 `CommandPlugin` 接口。但应用选择、绑定创建、应用设置页面和专用启用字段仍在宿主中，是需要收敛的功能特例。

增加更多内置功能前，应将功能专用配置与设置页面交给插件，宿主保留窗口容器、通用绑定控件、配置存储及生命周期管理。宿主仅在装配入口引用具体插件；通用分发和注册逻辑不增加按功能类型判断的分支。内置插件停用后应释放其资源，保留配置。
